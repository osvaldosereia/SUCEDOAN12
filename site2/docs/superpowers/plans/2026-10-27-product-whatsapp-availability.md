# Product WhatsApp Availability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let authorized staff change only the WhatsApp availability flag of a product through the Admin.

**Architecture:** Add a service-only Postgres RPC that checks staff role, expected current state and Flow readiness, then atomically updates `products.is_whatsapp_active` and writes `admin_audit_logs`. A dedicated authenticated Edge Function exposes the narrow operation; the product detail page uses a separate explicit action.

**Tech Stack:** Supabase PostgreSQL, Supabase Edge Functions/Deno, Next.js App Router, TypeScript, existing Supabase SSR adapters, Biome.

**Spec:** `docs/superpowers/specs/2026-10-27-product-whatsapp-availability-design.md`.

## Global Constraints

- Canonical Supabase is `ssbesxgaijknwsjbsbcz`; production remains read-only in this plan.
- Never read or expose secret values, product cost, fiscal data, or raw database/provider payloads.
- The operation changes only `is_whatsapp_active` and `updated_at`, with an audit row in the same transaction.
- Only active `owner`, `admin`, and `catalog_manager` memberships can change the flag; the Edge Function and RPC both check that allowlist.
- Do not modify Meta catalog links or publish products/Flows; do not send WhatsApp, write Bling, or issue NF-e.
- Do not add or run automated tests. Use focused static checks only.

## Review Focus

- Stale form state: if the current state already matches the requested target, return idempotent success; otherwise compare the expected flag and return conflict without mutation when stale.
- Enabling an inactive, nameless, image-less, HTTP-image, or invalid-price product: reject before update.
- Disabling a product that no longer meets Flow criteria: still permit the safety action.
- Audit insert failure: roll back the product flag change with the same RPC transaction.
- Unrelated product fields, cost, stock, fiscal metadata, catalog mappings, and Meta state: remain untouched.
