**Data:** 09/10/2026. **Sistema:** Dona Antônia, branch GitHub agent/gondola-labels-balance-20261009, PR #987 em DRAFT. **Ambiente de teste:** Supabase staging jxfxyqcpxoykdxbapswi, branch da6-qa-20261009. **Natureza:** teste funcional remoto com imagens sintéticas 1×1; não é QA física ou autorização de deploy.

## Solução de teste independente por trace
O utilitário QA tests/da6-hosted-batch-session-qa-edge.ts (commit 94303b43214b708efdbb8c58133b540b2d9094da) foi implantado **somente** em Supabase staging sob nome da6-qa-batch-session v1, temporariamente verify_jwt=false com validação obrigatória de chave x-da6-worker-key do Vault e URL staging fixa. O utilitário abre uma única conta sintética e um único lote com 50 ou 100 arquivos. Para evitar o limite documentado de chamadas Edge→Edge aninhadas dentro de um trace, cada chamada subsequente envia **apenas dez fotos**, em um trace separado, autenticando pela mesma conta e continuando o mesmo lote.

Em cada uma das dez fotos de cada chamada:
1. O Auth fornece JWT de operador artificial válido e o gateway confirma o papel.
2. O gateway reserva a foto via RPC de banco, cria URL assinada privada com Storage.
3. O cliente com chave pública (anon) faz uploadToSignedUrl de PNG distinto com checksum SHA-256 individual.
4. O gateway confirma a presença e o tamanho, altera estado para queued.
5. O servidor mantém todos os resultados no mesmo batch_id. Não há foto, contato, produto, WhatsApp ou cliente real.

O teste final verifica o total de fotos queued pelo endpoint inventory_label_batch_status, chama uma vez o worker remoto com chave do Vault (que rejeita corretamente 1×1 por dimensão) e depois apaga TODOS os registros, usuário Auth e objetos Storage.
